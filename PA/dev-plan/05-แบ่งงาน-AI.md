# แบ่งงาน AI — ซับซ้อนคนนี้ / ง่ายคนอื่น

อ่าน [`00-กฏเหล็ก.md`](00-กฏเหล็ก.md) ก่อนรับซองทุกครั้ง  
ส่งซองละหนึ่งเรื่อง อย่าให้ตัวง่ายแตะสูตรหรือสิทธิ์ข้ามสาย

ระบบจริงเขียนด้วยสแตกบังคับเท่านั้น: React + HTML/CSS + Tailwind เรียก API; แบ็กเอนด์เป็น Node.js (Express) หรือ Python (FastAPI) หรือ C# (.NET) พร้อม JWT; ฐาน MySQL สำหรับ schema/CRUD  
เดโม `demo/js/app.js` เป็นโครงจออ้างอิง ซองใหม่ห้ามขยายสแตติก HTML ให้เป็นระบบจริง และห้ามเปลี่ยนสแตก

## ส่วนที่ตัวนี้ (แผนนี้ / เอเจนต์หลัก) เขียนเอง — งานซับซ้อน

| รหัสซอง | งาน | ทำไมไม่ส่งต่อ |
| --- | --- | --- |
| C1 | เครื่องคำนวณหน่วยอาจารย์ `criteria.js` ตารางประกาศ ทุน บทบาท เพดานกลุ่ม ฐาน 1,820 | สูตรปนกันง่าย ผิดแล้วคะแนนทั้งคณะเพี้ยน |
| C2 | ตาราง SHPA หัวใจ (บทความ/โครงการ หลายคอลัมน์เกณฑ์) | ผูกประกาศกับฟอร์ม ห้ามทำให้เป็นตารางข้อตกลงทั่วไป |
| C3 | เครื่องสถานะทั้งวงจร PA+CC คู่กัน ไม่เห็นด้วย ล็อกหลังส่ง | เงื่อนไข PMS2 ไขว้กัน |
| C4 | เมทริกซ์บทบาทและกันสายปน (อาจารย์ไม่เห็นแบบ 05–09) | เคยพังซ้ำถ้าแยกไม่ครบ |
| C5 | Mapping ป้าย หัวหน้างานขั้นต้น/หัวหน้างาน ทั้งที่สตอเรจเก่ายังเป็น committee/chair | ต้องคงความหมายต้นทาง |
| C6 | สูตรสมรรถนะ UM-01 และการรวม 80+20 | มีสูตรและข้อยกเว้น FC/MC |
| C7 | กติกาประเมินผลงานแบบตัวเลข+ตนเอง โดยไม่ทิ้งหลักฐานในข้อตกลง | คำสั่งเจ้าของงานตัดกับสไลด์ PMS |
| C8 | เมื่ออัปโหลด Word 05–09 และไฟล์ 04 แล้ว: คัดคอลัมน์/rubrics เข้า config แล้วผูกฟอร์ม | ต้องอ่านต้นฉบับทีละช่อง ห้ามเดา |
| C9 | โครง React + Tailwind แยกหน้าตามบทบาทและสาย เรียก API อย่างเดียว ไม่คิดเกณฑ์ในคอมโพเนนต์ | สิทธิ์ข้ามสายกับสูตรเดียวกับ C1–C7 |
| C10 | แบ็กเอนด์ที่เลือกจาก `stack.backend.allowed` + JWT + REST และ/หรือ GraphQL ของวงจรสถานะ | ตรรกะธุรกิจอยู่ที่นี่ ไม่ใช่ที่ UI |
| C11 | MySQL schema ของผู้ใช้ รอบ ชุดประเมิน ข้อตกลง คะแนน IDP ตามช่องต้นฉบับ | ห้ามเพิ่มคอลัมน์วิเคราะห์เอง |

อย่าให้ตัวอื่น merge โค้ดทับไฟล์เหล่านี้โดยไม่มีผู้ตรวจซอง C

## ส่วนที่เหมาะให้ AI ตัวอื่นเขียน — งานง่าย ซองละชิ้น

แต่ละซองต้องส่ง: (1) รายการไฟล์ที่จะแตะ (2) ห้ามแตะไฟล์ในซอง C (3) คัดลอกข้อความจากต้นฉบับเท่านั้น (4) ทดสอบว่าบทบาทอื่นยังเข้าหน้านี้ไม่ได้

| รหัสซอง | งาน | ไฟล์ที่แตะได้โดยประมาณ | อย่าทำ |
| --- | --- | --- | --- |
| S1 | คัดชื่อเมนูและ crumb จากบัญชีเอกสารเป็นข้อความบนจอ | `app.js` เฉพาะสตริงโมดูล STAFF_MODULES | อย่าเปลี่ยน logic สิทธิ์ |
| S2 | หน้าช่วยเหลือ: วาง bullet จากคู่มือตามบทบาท | `viewHelp` | อย่าเขียนคำแนะนำที่ไม่มีในเล่ม |
| S3 | ตารางปฏิทินรอบ กิจกรรม/วันเริ่ม/วันสิ้น ตามไฟล์ 02 เมื่อมีไฟล์ | `viewAdminRound` | อย่าคิดวันที่เอง ถ้าไม่มีไฟล์ใช้ช่องว่าง |
| S4 | หน้าโปรไฟล์: ป้ายช่องตาม UM-03 | `viewProfile` | อย่าเพิ่มช่องที่ไม่มีในตารางประวัติ |
| S5 | CSS ตัวอักษรใหญ่ สีตัด ตามเดโมที่มี ไม่ออกแบบธีมใหม่ | `app.css` | อย่าย้ายเลย์เอาต์ตาราง SHPA |
| S6 | หน้าพิมพ์รายงาน 2 หน้า: สรุป + ตารางรายการ ใช้ป้ายจาก labelMap | `viewReport` | อย่าใส่คอลัมน์รายงานยาว |
| S7 | แบบทดสอบสตริง: ห้ามมีกรรมการประเมิน/ประธานกรรมการบนจอผู้ใช้ | ต่อจาก `labels.test.js` | อย่าลบคำประธานออกจากเกณฑ์ภาระงานโครงการในประกาศ |
| S8 | เมื่อได้ไฟล์ 05_สน.docx: ทำตาราง HTML คอลัมน์ตาม Word ทีละหัวตาราง | หน้า support PA | อย่าหยิบคอลัมน์จากแบบวิชาการไปใส่ |
| S9 | เมื่อได้ไฟล์ 06: ช่องความก้าวหน้า ปัญหา ความช่วยเหลือ ตามหัวใน Word | `viewFollow` | อย่าบังคับเปอร์เซ็นต์ถ้า Word ไม่บังคับ |

| S12 | เมื่อได้ไฟล์ IDP ผู้ปฏิบัติ/ผู้อนุมัติ: แยกข้อความคำชี้แจงสองฝั่ง | `viewIdp` `viewIdpEval` | อย่าเปลี่ยนผล IDP เป็นคะแนน 0–10 |

| S14 | รายการรายงานภาพรวมชื่อตาม PMS2 (รายชื่อรายงานอย่างน้อยตาม digest) เป็นเมนู ยังไม่ต้องมีข้อมูลจริง | `viewReport` เมนูย่อย | อย่าคิดชื่อรายงานใหม่ |
| S15 | อังกฤษ: สลับชุดไฟล์ 05/07/08 ที่มีคำว่า Eng เมื่อ `lang=en` | สตริงป้าย | อย่าแปลเกณฑ์ประกาศไทยเอง |
| S16 | คัดลอกไฟล์เดโม เปิดตรงนี้.html zip ตามสคริปต์ที่มี | `build-opener.js` | อย่าแก้สูตรใน opener ด้วยมือ อย่าถือว่าเดโมนี้คือสแตกบังคับ |
| S17 | หน้า React ตามเดโม: login โปรไฟล์ ช่วยเหลือ ใช้ Tailwind ไม่คิดคอมโพเนนต์ไลบรารีใหม่ | โฟลเดอร์ frontend | อย่าเรียกฐานข้อมูลตรงจากเบราว์เซอร์ |
| S18 | CRUD MySQL ตารางที่ schema กำหนดแล้ว ผ่าน REST ของแบ็กเอนด์ที่เลือก | โฟลเดอร์ backend + SQL | อย่าเปลี่ยน engine เป็นอย่างอื่น |

## ประโยคใส่ต้นพรอมต์ของ AI ตัวง่าย

```
อ่าน PA/dev-plan/00-กฏเหล็ก.md และ pa-config.example.json
ทำเฉพาะซอง Sxx ตาม 05-แบ่งงาน-AI.md
สแตกบังคับ: React + HTML/CSS + Tailwind เรียก API; backend เป็นหนึ่งใน Node.js Express / Python FastAPI / C# .NET พร้อม JWT; ฐาน MySQL
ห้ามคิดสแตก ช่อง หรือเกณฑ์เอง ถ้าเจอ SOURCE_MISSING ให้หยุดแล้วบอกว่าไฟล์ต้นฉบับยังไม่มี
ห้ามแก้สูตรใน criteria และเครื่องสถานะนอกสตริงที่ซองระบุ
อาจารย์กับสายสนับสนุนแยกเมนู ห้ามโชว์ข้ามสาย
ป้ายผู้ประเมินบนจอคือ หัวหน้างานขั้นต้น และ หัวหน้างาน
```
