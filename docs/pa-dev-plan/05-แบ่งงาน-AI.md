# แบ่งงาน — แกนยากกับซองงาน

อ่าน [`00-กฏเหล็ก.md`](00-กฏเหล็ก.md) และ [`pa-config.example.json`](pa-config.example.json) ก่อนรับซองทุกครั้ง  
ส่งซองละหนึ่งเรื่อง ห้ามแตะสูตรหรือสิทธิ์ข้ามสาย  
**ยังไม่ลงมือเขียนแกนโปรแกรมในรอบนี้**

สแตกที่สร้างจริง: React + HTML/CSS + Tailwind เรียกบริการ Node.js (Express) ค่า `stack.backend.chosen` = `Express` การพิสูจน์ตัวตนด้วย JWT ฐาน MySQL  
FastAPI และ .NET เป็นทางเลือกในเอกสารเท่านั้น ห้ามสร้างคู่ขนาน

## งานที่หัวหน้าชุดนี้เขียนภายหลังเท่านั้น (แกนยาก)

| รหัส | งาน |

| C3 | เครื่องสถานะข้อตกลงการปฏิบัติงานคู่กับสมรรถนะหลัก การไม่เห็นด้วย การล็อกหลังส่ง |
| C4 | แยกสายวิชาการกับสายสนับสนุน แต่ละบทบาทเห็นเฉพาะหน้าของตน |

## สัญญาการคืนซอง

ทุกซองที่ส่งคืนต้องมีหัวข้อครบดังนี้ ขาดข้อใดถือว่าไม่ครบ

1. รหัสซอง
2. รายการไฟล์ที่แตะ ทุกเส้นทาง
3. รายการตัวแปรที่ใช้ ทุกตัวต้องมีอยู่แล้วใน `pa-config.example.json` **ห้ามเพิ่มฟิลด์ใหม่**
4. ค่าที่เป็น `SOURCE_MISSING` ต้องคงคำนี้ ห้ามเติมเกณฑ์
5. ผลตรวจเข้ากันได้ตามรายการด้านล่าง

รูปแบบหัวข้อคืนงาน

```
ซอง: Sxx
ไฟล์ที่แตะ:
- เส้นทางไฟล์
ตัวแปรที่ใช้:
- stack.frontend
- labelMap.firstHead
SOURCE_MISSING:
- ไม่มี หรือระบุคีย์
ตรวจเข้ากันได้: ผ่าน / ไม่ผ่าน พร้อมข้อที่ตก
```

## รายการตรวจเข้ากันได้

- สแตกจอเป็น React HTML/CSS Tailwind และเรียกบริการเท่านั้น
- ส่วนบริการที่สร้างเป็น Express ตาม `stack.backend.chosen` ไม่มี FastAPI หรือ .NET ในคลังรหัส
- ฐานข้อมูลเป็น MySQL
- ตัวแปรทุกตัวมีใน `pa-config.example.json` ไม่มีฟิลด์ใหม่
- สายวิชาการไม่เห็นแบบ 05 ถึง 09 สายสนับสนุนไม่เห็นตารางหน่วยตามประกาศสายวิชาการ
- ป้ายบนจอเป็นหัวหน้างานขั้นต้นและหัวหน้างาน ตาม `labelMap`
- `paReport.mode` เป็นตัวเลขและประเมินตนเอง ไม่มีรายงานยาว
- `form11.enabled` เป็นเท็จ จึงไม่เปิดแบบคำมั่น
- สิทธิ์ตามบทบาทใน JWT ไม่มีปุ่มสลับบทบาทบนหน้าผู้รับการประเมิน
- สูตรหน่วย สูตรสมรรถนะ และเครื่องสถานะไม่ได้ถูกแก้ในซอง S
- ช่องที่ต้นฉบับยังไม่มีติด `SOURCE_MISSING`
- บัญชี `unitPaFy2570` ไม่ถูกผูกเข้า `faculty.totalUnits`
- แบบ `facultyResearchTracking2570` ไม่เปิดในสายสนับสนุน และไม่ถูกใช้คิดหน่วย
