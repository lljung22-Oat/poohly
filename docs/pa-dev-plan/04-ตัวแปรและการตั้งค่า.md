# ตัวแปรและการตั้งค่า — ให้ AI ตัวอื่นอ่านแล้วใช้ซ้ำ

ทุกค่าที่เกี่ยวกับเกณฑ์ ป้าย น้ำหนัก สถานะ ต้องอยู่ใน config ห้ามฮาร์ดโค้ดข้อความไทยในหลายไฟล์โดยไม่ผ่านตัวนี้

ถ้าค่าเป็น `null` หรือ `"SOURCE_MISSING"` ห้ามเดา ให้ UI เว้นว่างหรือซ่อนฟีเจอร์นั้น

## สถานะภายใน (รหัสอังกฤษ ป้ายไทยจาก labelMap)

`draft` `wait` `back` `approved` `reported` `firstHead` `head` `ack` `disagree`  
IDP เพิ่ม `idpWait` `idpApproved` `idpReported` `idpEval` `idpAck`

อย่าใช้คำว่า committee/chair บนจอ ใช้ได้เฉพาะรหัสเก่าในสตอเรจแล้ว map ตอนอ่าน

## กฎการคำนวณที่อนุญาตให้เขียนโค้ด

1. น้ำหนักข้อตกลงรวมและน้ำหนักตัวชี้วัดต่อข้อ — ตาม UM-03 / PMS
2. หน่วยอาจารย์จากตารางประกาศใน `criteria.js` คูณบทบาท 100% หรือ 50% ตามประกาศ
3. งานวิจัยร่วมนักศึกษาในยุทธศาสตร์ไม่นับ — ตามประกาศที่คัดแล้ว
4. สูตร CC ของ UM-01
5. รวม `(paScore * 80/100) + (ccScore * 20/100)` ตาม Dialog ตัวอย่าง PMS ถ้าส่วนงานไม่ได้ประกาศสัดส่วนอื่น
6. สูตรร้อยละของบัญชีส่วนงานที่เล่ม 2570 เขียนครบเท่านั้น: 2.2.1 2.2.2 2.3 4.10.1 4.10.2 4.11.3 4.11.4 และวิธีตัด Baseline SciVal ของผลงานตีพิมพ์ — ใช้เมื่อทำชั้นส่วนงาน ห้ามเรียกจากสูตรหน่วยอาจารย์

นอกนั้นเป็นข้อความ/ไฟล์/ตัวเลือกจากต้นฉบับ

## ข้อมูลต่อคนที่ต้องมี (จากหน้าประวัติ UM-03 และสไลด์ชุดประเมิน)

เก็บได้เฉพาะช่องที่ฟอร์มต้นทางมี เช่น ชื่อ รหัสบุคลากร ตำแหน่ง ประเภท ภาควิชา/งาน ส่วนงาน อีเมล ผู้ประเมิน วันที่เริ่มงานถ้ามีในแบบ  
ห้ามเพิ่มฟิลด์วิเคราะห์เอง

ชุดประเมินต่อคนต่อรอบ: รายการ `{ formType: PA|CC|IDP|FC|MC, status, enabled }`

Frontend เรียกแบ็กเอนด์ผ่าน REST และ/หรือ GraphQL เท่านั้น เก็บสถานะวงจรและ CRUD ใน MySQL ห้ามใช้ localStorage เป็นแหล่งความจริงของระบบจริง Authentication ใช้ JWT ที่แบ็กเอนด์ออกให้
